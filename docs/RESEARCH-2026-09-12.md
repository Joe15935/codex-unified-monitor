# Open-source research and bounded development · 2026-09-12

Research used the GitHub connector first to read public repository metadata,
default-branch commits, README files, release inventories and selected source
files. Values below are observations from 2026-09-12, not ongoing guarantees.
Repository push dates can include branches other than `main`; both dates are
shown where that distinction matters. Download sizes are not measured RAM use.

## Recommended route

Extend the existing Tauri 2 / Rust / SQLite application. Its current official quota
readings, local token ledger, cache metrics, bilingual UI, three export formats and
Tier Auditor already cover the core use case. A replacement application or new UI
framework would increase maintenance and remove existing functionality.

Keep this development increment to four areas:

1. Windows paths, Codex executable discovery, background child-process behavior,
   tray/login integration, native CI and a current-user NSIS installer. A successful
   build and native runtime acceptance remain separate gates.
2. Optional adaptive refresh with coalescing and a fixed cadence during active
   audits. Use existing app/window and file-watcher activity, not broad process or
   filesystem scans. CodexBar's [pure scheduling policy](https://github.com/steipete/CodexBar/blob/a998f677dd1fa0c8bfe242e177057e20d57333d9/Sources/AdaptiveRefreshCore/AdaptiveRefreshPolicyCore.swift)
   and [refresh-loop documentation](https://github.com/steipete/CodexBar/blob/a998f677dd1fa0c8bfe242e177057e20d57333d9/docs/refresh-loop.md)
   are the reference, not a requirement to use all of its signals or timings.
3. Small, visible quota/data-health cues. Any optional desktop notification should
   use current official readings and deduplicate by account, window and reset
   cycle, including minor reset-time corrections; see CodexBar's
   [notification logic](https://github.com/steipete/CodexBar/blob/a998f677dd1fa0c8bfe242e177057e20d57333d9/Sources/CodexBar/PredictivePaceWarnings.swift).
4. Conservative compatibility with newly recorded Codex service-tier settings,
   with regression tests for token identity and auditing controls.

Recommendations are not acceptance claims. Consult [TEST_REPORT.md](../TEST_REPORT.md)
for what actually shipped and which platforms were exercised. No multi-provider
hub, account switching, telemetry, cloud database, remote messaging or chat/model
control is needed for this scope.

## Implemented parser change and official evidence

`crates/core/src/parser.rs` now recognizes
`event_msg/thread_settings_applied.thread_settings.service_tier`. The gap was
identified by reviewing ccusage's [parser](https://github.com/ccusage/ccusage/blob/aaa8992341cbe7ee7a534e662831b2b76c43eda1/rust/adapters/codex/src/parser.rs#L303).
The implementation here was independently written for this application's existing
parser; no source code from these newly researched projects was copied.

The official [ThreadSettingsAppliedEvent and ThreadSettingsSnapshot](https://github.com/openai/codex/blob/c4017a87aacc7558002b7cb510025e967c1d765e/codex-rs/protocol/src/protocol.rs#L2190)
establish the nested shape and optional logical owner. Copied snapshots can retain
their original owner's ID. The official [service-tier mapping](https://github.com/openai/codex/blob/c4017a87aacc7558002b7cb510025e967c1d765e/codex-rs/protocol/src/config_types.rs#L527)
accepts Fast/priority and explicitly distinguishes default routing. The
[thread-settings writer](https://github.com/openai/codex/blob/c4017a87aacc7558002b7cb510025e967c1d765e/codex-rs/core/src/session/thread_settings.rs#L122)
emits thread-owned snapshots. The
[turn-context implementation](https://github.com/openai/codex/blob/c4017a87aacc7558002b7cb510025e967c1d765e/codex-rs/core/src/session/turn_context.rs#L949)
also permits per-turn service-tier overrides after persisting thread settings.

For this reason the monitor deliberately retains a stricter evidence boundary
than an indefinite inheritance rule:

- Accept a settings record only after a session header, for the current logical
  thread (or an older ownerless record), with a valid timestamp and outside the
  already recognized inherited fork prefix.
- Preserve recognized wire values. Fast, priority, flex and batch remain
  non-standard values that the Auditor excludes.
- A missing service-tier field adds no evidence and leaves current state alone.
  Explicit null, malformed or unrecognized values clear current tier evidence.
- A later `turn_context` replaces current tier evidence. If that turn lacks a tier,
  it remains unknown; an earlier thread setting is not proof of Fast-off for a
  later request. Explicit unknown/null on a token record also overrides a known
  setting rather than falling back to it.
- Token arithmetic, identities, model names and prices are unchanged. No historic
  rows are rewritten or assigned a newly inferred speed. Existing unknown-speed
  audit intervals retain their confidence limitation.

Targeted synthetic tests are in `crates/core/tests/parser_thread_settings.rs`:

```sh
cargo test --manifest-path crates/core/Cargo.toml \
  --test parser_thread_settings --test accounting_ingest --test tier_auditor
```

## Deferred: MultiAgent replay-boundary heuristics

ccusage's [format notes](https://github.com/ccusage/ccusage/blob/aaa8992341cbe7ee7a534e662831b2b76c43eda1/rust/adapters/codex/src/README.md)
describe `task_started` and `inter_agent_communication_metadata` / legacy
`inter_agent_communication` with `trigger_turn=true` as replay markers. The official
[rollout wire serializer](https://github.com/openai/codex/blob/c4017a87aacc7558002b7cb510025e967c1d765e/codex-rs/history/src/rollout_payload.rs#L75)
confirms the metadata record and boolean exist. The inspected ccusage parser did
not establish the claimed marker implementation, and the official evidence read
here does not establish a universal boundary for all resumed/forked rollout shapes.

This release therefore does not add a new replay heuristic based only on those
markers or a CLI version. Existing record ownership, deduplication and known
fork-prefix handling remain. A future change needs concrete producer ordering and
fixtures covering original, copied, resumed and missing-parent histories, without
ever retaining message/tool contents in the monitor's database.

## Performance follow-up: reuse patterns without another framework

The follow-up review used the current primary sources below. These are design
references, not evidence that another application has the same rendering issue.

- React's [memo guidance](https://github.com/reactjs/react.dev/blob/8efce7853d0fc59e615ed1c253799cf1798b8428/src/content/reference/react/memo.md#L127)
  recommends keeping transient state local and profiling specific slow work.
  [External-store guidance](https://github.com/reactjs/react.dev/blob/8efce7853d0fc59e615ed1c253799cf1798b8428/src/content/reference/react/useSyncExternalStore.md#L44)
  requires stable snapshots when data is unchanged.
- TanStack Query's [focus manager](https://github.com/TanStack/query/blob/1585f2f6d1128b8e41723c86b9b6051e7e8a6352/packages/query-core/src/focusManager.ts#L20)
  watches document visibility and cleans up listeners. SWR's
  [request handling](https://github.com/vercel/swr/blob/01cb4888a1abc96b279fbf771c084b46c575bf53/src/index/use-swr.ts#L588)
  discards superseded responses; its polling loop schedules the next attempt
  after completion. Both are maintained MIT-licensed libraries, but these small
  coordination rules fit the existing local-data helpers without installing a
  query framework.
- CodexBar's [menu-open refresh policy](https://github.com/steipete/CodexBar/blob/a998f677dd1fa0c8bfe242e177057e20d57333d9/Sources/CodexBar/MenuOpenRefreshPlan.swift#L23)
  provides a useful reference for refreshing stale visible data on opening a
  window instead of triggering unrelated expensive work.
- The installed Tauri 2.11.5 [background-throttling documentation](https://github.com/tauri-apps/tauri/blob/7cd71369c00978a3783b6ae3e9972358abbe4ae6/crates/tauri/src/webview/webview_window.rs#L1189)
  describes suspension of hidden/minimized webviews and platform restrictions
  on policy overrides. This does not establish the cause of a particular blank
  window. Focus/visibility refresh, native painting, frontend readiness and live
  collection need separate acceptance evidence; disabling background throttling
  or repeatedly resizing the window is not a demonstrated fix.

The formatting optimization implemented here is an independently written, bounded
cache of `Intl.NumberFormat` and `Intl.DateTimeFormat` instances. It keeps at most
six number formatters and sixteen locale/timezone combinations, caches no usage
values, and retains existing English/Chinese output, currency rounding, null/zero
timestamp behavior and errors. This removes repeated formatter construction from
ordinary redraws without changing the public formatting API or adding a dependency.
`tests/formatters.test.mjs` checks output parity, locale changes, midnight/DST
boundaries and cache limits. An isolated formatter microbenchmark is a narrow
implementation check, not a whole-application startup or frame-rate claim.
